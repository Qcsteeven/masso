# Фаза $ARGUMENTS

Состояние репозитория:
- Последние коммиты: !`git log --oneline -8 2>/dev/null || echo "нет коммитов"`
- Незакоммиченное: !`git status --short 2>/dev/null | head -30`

## Порядок

1. Прочитай в `docs/03-plan.md` раздел «Фаза $ARGUMENTS» целиком и все разделы `docs/02-mvp-spec.md`, на которые он ссылается. Просмотри `docs/DEVIATIONS.md`.
2. Если код уже есть — обзор текущего состояния сделай через Explore-субагента, чтобы не тратить основной контекст.
3. Покажи план: какие файлы создашь/изменишь, порядок шагов, какие тесты докажут каждый пункт «Готово, когда», какие места спеки неоднозначны. **Дождись подтверждения**, если пользователь не написал «без подтверждения».
4. Реализуй небольшими шагами. После каждого шага — тесты этого шага. Перед API библиотек, в которых не уверен, — Context7.
5. Прогони `make check` через агента `test-runner`; для фаз с Docker — ещё `make test-integration`. Чини до зелёного.
6. Отдай дифф агенту `reviewer` с номером фазы. Исправь «Критично» и «Важно», повтори ревью при критичных находках.
7. Любой осознанный отход от ТЗ/ТП/спеки — строка в `docs/DEVIATIONS.md`.
8. Отметь выполненные чекбоксы фазы в `docs/03-plan.md`. Коммит: `phase-$ARGUMENTS: <кратко что сделано>`.
9. Итог пользователю — 3–5 строк: что готово, чем доказано (команды/тесты), что осталось или вызывает сомнения.

Не начинай следующую фазу в этой же сессии — пользователь сделает `/clear` и вызовет её отдельно.
