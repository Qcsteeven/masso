# Синхронизация ТЗ/ТП с реализацией

Цель — файл `docs/doc-updates.md`, по которому Лев правит ТЗ и ТП (docx у него, здесь PDF только для чтения).

1. Прочитай `docs/DEVIATIONS.md` и раздел 4 `docs/01-scope.md`.
2. Сверь с кодом то, что могло разойтись без записи в журнал: имена таблиц и полей (миграции Alembic) против ТЗ 4.5 и ТП рис. 21/табл. 2; эндпоинты (OpenAPI `/api/docs` или роутеры) против ТП табл. 8; WS-каналы против ТП табл. 9; справочники статусов против ТП табл. 5–6; состав контейнеров docker-compose против ТП рис. 26 и 29; стек и версии (`uv.lock`, `pnpm-lock.yaml`) против ТЗ табл. 2.
3. Нужные страницы PDF читай точечно (`docs/rev2/TZ.pdf`, `docs/rev2/TP.pdf`, параметр pages; исходники DOCX — `docs/rev2/*.docx`).
4. Запиши `docs/doc-updates.md`:
   - Таблица ТЗ: пункт | было (кратко) | стало (готовая формулировка для вставки) | почему.
   - Таблица ТП: то же.
   - Рисунки на перерисовку: номер, что изменить. Требования к диаграммам: только монохром (чёрный/белый/светло-серый), изменения выделять жирным; sequence — актор-человечек, линии жизни пунктиром, элементы исполнения, синхронный вызов — закрашенная стрелка, ответ — пунктир, REST — «метод + URL», нумерация сообщений.
   - Новые рисунки, которые стоит добавить (например, «первая очередь vs целевая архитектура»).
5. Не правь сами PDF. В конце — 3 строки: сколько правок в ТЗ, в ТП, сколько рисунков.
