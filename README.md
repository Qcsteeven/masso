# МАССО — стартовый набор для реализации в Claude Code

Этот каталог — корень будущего репозитория. Кода здесь ещё нет: здесь всё, чтобы Claude Code написал систему по фазам и не расползся.

| Файл | Зачем |
|---|---|
| `docs/01-scope.md` | Что оставить, упростить, отложить; правки ТЗ/ТП; найденные ошибки в документах |
| `docs/02-mvp-spec.md` | Спецификация первой очереди: данные, API, алгоритмы, песочница, агенты, испытания |
| `docs/03-plan.md` | 10 фаз с критериями «Готово, когда» — это и есть «капитальный промпт», разбитый на части |
| `CLAUDE.md`, `.claude/rules/` | Постоянные правила для Claude (общие + отдельно backend/frontend/песочница, грузятся по путям) |
| `.claude/agents/` | `reviewer` (Opus, независимое ревью диффа), `test-runner` (Haiku, прогон проверок без мусора в контексте), `ui-checker` (Sonnet + Playwright, сверка экранов с макетами) |
| `.claude/skills/` | `/phase N` — провести фазу по плану; `/sync-docs` — собрать правки ТЗ/ТП по факту реализации |
| `.claude/settings.json` | Разрешения (make/uv/pnpm/docker compose без вопросов, push — с вопросом, `.env` и исходные PDF — запрещены) + хук автоформатирования |
| `.mcp.json` | Context7 — актуальная документация библиотек (LangGraph, FastAPI, aiodocker, React) |
| `docs/DEVIATIONS.md` | Журнал отходов от ТЗ/ТП, который Claude ведёт сам |

## 1. Подготовка (один раз)

1. Стенд: Linux (ВМ или своя машина) с Docker Engine + Compose, `uv`, Node 24 LTS + `pnpm`, `python3`, `git`. Для `ui-checker` нужен `npx` (Playwright MCP сам скачает браузер).
2. Claude Code: установка по [quickstart](https://code.claude.com/docs/en/quickstart), вход аккаунтом claude.ai.
3. Репозиторий:
   ```bash
   cd masso && git init && git add -A && git commit -m "chore: claude code kit"
   cp .env.example .env          # вписать ключ LLM-провайдера или оставить local/template
   ```
   Макеты экранов уже в `docs/mockups/` (Claude Design, см. README там).
4. Первый запуск `claude` в каталоге: принять доверие к папке и подключение `context7` из `.mcp.json` (проверка — `/mcp`).
5. Плагины (по желанию, через `/plugin`): code intelligence для Python и TypeScript — Claude видит ошибки типов сразу после правки; `security-guidance` — доп. проверки на каждое редактирование, полезно для auth и песочницы.

Модели: основная сессия — Opus (`/model`), effort высокий для фаз 4–7. Субагенты уже назначены: ревью на Opus, прогоны тестов на Haiku, UI на Sonnet. GitHub — через `gh` CLI, отдельный MCP не нужен; БД — через `docker compose exec db psql`, MCP для Postgres тоже не нужен (меньше инструментов — чище контекст).

## 2. Рабочий цикл

```text
/clear
/phase 0
```

Claude читает раздел плана и спеку, показывает план, ждёт «ок», реализует, гоняет `make check` через `test-runner`, отдаёт дифф `reviewer`, отмечает чекбоксы, коммитит. Ты проверяешь план и итог, дальше — `/clear` и `/phase 1`.

Полезное:
- **Режим разрешений.** В свежих версиях по умолчанию auto mode (классификатор сам пропускает безопасные действия). `Shift+Tab` переключает режимы; для обсуждения без правок — plan mode.
- **`/goal`** — довести фазу до конца без пинков: `/goal make check зелёный и все чекбоксы фазы 5 в docs/03-plan.md отмечены, или остановись через 30 ходов`.
- **Параллельно фронт и бэк** (с фазы 8, когда API стабилен): вторая сессия в отдельном git worktree (`claude --worktree`), чтобы правки не конфликтовали.
- **`/code-review`** — встроенное ревью текущего диффа на баги в чистом контексте; дополняет `reviewer`, который сверяет со спекой.
- **`/run-skill-generator`** после фазы 0 — Claude запишет рецепт запуска стенда, и `/verify` будет проверять изменения на живом приложении.
- Если Claude дважды ошибся в одном и том же — `/clear` и переформулировать задачу; если ошибка повторяется между сессиями — добавить правило в `CLAUDE.md` или `.claude/rules/`.
- Перед сдачей: `/sync-docs` → `docs/doc-updates.md` с готовыми формулировками для ТЗ и ТП и списком рисунков на перерисовку.

## 3. LLM для самой системы

Код работает с любым OpenAI-совместимым API (`.env`): внешний провайдер, локальный Ollama/vLLM (`docker compose --profile llm up`) или вообще без LLM — режим `template` на заранее подготовленных вариантах сценариев. Для демо на защите режим `template` — страховка от недоступности сети.
