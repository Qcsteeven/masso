# МАССО: что оставить, что упростить, что отложить

> Выполнено 17.10.2026: правки из этого файла внесены в ТЗ и ТП редакции 2 (`docs/rev2/`), перечень — `docs/rev2/CHANGES.pdf`. Номера рисунков ниже — по редакции 1.

Анализ ТЗ (`docs/source/TZ.pdf`) и ТП (`docs/source/TP.pdf`) перед реализацией опытного образца. Принцип: **ТЗ/ТП описывают целевую архитектуру, опытный образец — первую очередь создания АС** (ГОСТ 34.602-2020 допускает очередность). Документы не переписываются целиком: в каждый добавляется одна таблица «Целевая архитектура → первая очередь» и правятся точечные места из раздела 4 этого файла.

## 1. Ядро — оставить без изменений

Без этого МАССО превращается в «спроси чатбота», поэтому это и есть сдаваемая ценность:

| Что | Почему ядро | Как сделать дёшево |
|---|---|---|
| Граф компетенций, дефициты, приоритеты, обновление уровней | Персонализация — главное отличие от статичных заданий | Детерминированный Python + SQL (recursive CTE), без LLM |
| Три агента на LangGraph (Profile, Scenario, Assessment) | Заявлено в названии и ТЗ 4.1.1 | LangGraph только там, где есть ветвление/цикл: генерация+валидация сценария и пост-обработка сессии. ProfileAgent — обычный сервис-узел |
| Валидация «существует путь решения» до публикации | Ответ на «а чем это лучше ChatGPT» | Для контейнерных сценариев — автопрогон: сломать → checks падают → эталонное исправление → checks проходят |
| Песочница Docker + веб-терминал; документный тренажёр | Практика, а не тест | Один контейнер на сессию, `network_mode: none`, cap-drop ALL |
| Цифровой след, инцидент ≤5 мин, ≤3 подсказок (−10 %), автопроверка, отчёт | Все проверяемые требования раздела 6.3 | Фоновый asyncio-цикл с состоянием в БД |
| Корректировка оценки преподавателем + аудит | ТЗ 4.2, сценарий 3 | Одна таблица audit_logs |
| Гибридный LLM-контур (внешний / локальный / шаблонный) | ТЗ 4.1.3, сценарий 5 | Один модуль поверх OpenAI-совместимого API + цепочка fallback |
| JWT + refresh в HttpOnly-cookie, RBAC, security_events | ТЗ 4.9 | FastAPI dependencies |

## 2. Упростить (та же функция, меньше инфраструктуры)

| Было в ТЗ/ТП | Стало в опытном образце | Почему |
|---|---|---|
| 4 хранилища: PostgreSQL + Neo4j + ChromaDB + Redis | **PostgreSQL 18 + pgvector** | Граф из 50–200 навыков — это 3 таблицы и recursive CTE. Векторы — колонка `vector`. Очереди/статусы — таблицы + asyncio. Минус 3 контейнера, 3 драйвера, синхронизация (весь п. 4.8 про недоступность Neo4j исчезает) |
| Сервисы: Backend, Agent Workers, LLM Gateway, Sandbox Manager, Verification Engine — отдельные контейнеры (рис. 26) | **Модульный монолит FastAPI**: каждый компонент C4 — пакет `backend/app/<component>/` | Те же границы и интерфейсы, один процесс. Компонентная диаграмма (рис. 27–28) остаётся верной |
| DevOps-среда генерируется LLM (docker-compose) | **Параметризуемые шаблоны** с каталогом сбоев (fault-скрипты) + эталонное исправление. LLM генерирует легенду, выбор/параметры сбоев, тексты подсказок и инцидента | LLM-сгенерированная инфраструктура ненадёжна и непроверяема; так генерация уникальна, а решаемость доказывается прогоном |
| Docker Compose-среда с `docker ps` внутри (Docker-in-Docker) | **Один контейнер-«сервер»**: nginx + app + postgres под supervisord от непривилегированного пользователя. Студент диагностирует через `supervisorctl`, логи, конфиги | DinD требует `--privileged` — прямо противоречит ТЗ 4.9. Если преподаватель настаивает на docker внутри — Sysbox (вторая очередь) |
| Кластер 50 сессий на 16 vCPU / 64 ГБ | Проверить на доступном стенде, целевое значение оставить | Контейнер-сервер ~200–300 МБ RAM; 20 сессий укладываются в 8 ГБ. Нагрузочный тест покажет реальное число |
| Next.js 16 (SSR) | **Vite + React 19 + TypeScript (SPA)** — рекомендовано, не обязательно | SSR не нужен; xterm.js и WebSocket — чисто клиентские. Если нужно оставить Next.js — static export, правок в ТЗ нет |
| xterm.js + Monaco + Recharts | xterm.js + Recharts; Monaco убрать | Файлы правятся в терминале (nano/vim) — это и есть навык |
| 4 WebSocket-канала (ТП табл. 9) | 2: `/ws/sessions/{id}/terminal`, `/ws/sessions/{id}/events` (статусы туда же) | Админ-мониторинг — polling раз в 10 с |
| Экспорт PDF/CSV/JSON через Export Worker и файловое хранилище (рис. 18) | CSV/JSON — синхронно с сервера; PDF — печатная версия страницы отчёта | Без очередей и хранилища |
| 5 ролей | 5 ролей в БД; у sysadmin в UI одна страница «Состояние системы» | Правок ТЗ не требует |
| 5 типов сценариев (ТЗ 4.3) | **2 движка** (контейнерный, документный) и **3 шаблона**: DevOps, юридический, аудиторский (= 3 пилотных направления п. 1.7). «Вводная клиента» — тип инцидента документного движка. ИБ — 4-й шаблон на контейнерном движке, если останется время | 100 % покрытия типов не через 5 реализаций, а через 2 движка + шаблоны |
| Семантическая проверка через ChromaDB | Embeddings через OpenAI-совместимый `/v1/embeddings`, косинус в pgvector/numpy; fallback — LLM-судья по рубрике | Порог 0.85 из ТЗ 4.10 сохраняется |

## 3. Отложить (вторая очередь)

Kubernetes; Prometheus + Grafana (оставить только `/metrics` и `/health`); Redis; Neo4j; ChromaDB; Export Worker; отдельные Event Collector / Hint Service (рис. 13) — это функции AssessmentAgent; сохранение альтернативных путей решения в базу знаний (сделать кнопкой «принять как альтернативное решение» → таблица, если останется время); 2FA (на макете рис. 42); импорт ICS (макет рис. 35).

### 4.2 Ошибки и несоответствия, найденные в документах

Исправить независимо от реализации — преподаватель придирчив.

1. **ТЗ 1.4**: дисциплина названа «Автоматизированные системы обработки информации и управления», а курс — «Проектирование АСОИиУ». Сверить с официальным названием.
2. **ТЗ 4.9**: тире вместо `--` (см. выше).
3. **ТП разд. 5**: «в четырех уровнях: концептуальном, логическом и физическом» — перечислены три.
4. **ТП рис. 27 и 28**: одинаковые подписи «C4 Component: backend и агенты»; в тексте «Компонентная диаграммы … приведены … Она показывает» — согласование. Рис. 28 → «C4 Component: агенты».
5. **ТП рис. 21** (физическая модель PostgreSQL): нет таблиц `security_events` и `agent_logs`, обязательных по ТЗ 4.5/4.9; имена расходятся с ТЗ (`learning_sessions`/`session_events` в ТП против `sessions`/`environment_events` в ТЗ). В реализации берём имена ТЗ.
6. **ТП табл. 2 / рис. 22**: атрибуты Skill не совпадают с ТЗ 4.5 (нет `domain`, `level_max`, `description`, `created_by`); вес висит на TARGETS, а по ТЗ 4.10 — на REQUIRES; на рис. 22 нет связи REQUIRES, зато сессии и результаты проверок продублированы в Neo4j (источник рассинхронизации).
7. **ТП рис. 9, 11, 12, 14, 15, 16**: сообщения без стрелок, актор — прямоугольник, нет пунктирных ответов, подписи наезжают на элементы исполнения. Рис. 10, 13, 17, 18 нарисованы правильно — привести остальные к ним (монохром, актор-человечек, закрашенная стрелка, пунктирный ответ, «метод + URL» для REST).
8. **ТП рис. 11**: в тексте ScenarioAgent сохраняет шаблон в PostgreSQL, на диаграмме участника PostgreSQL нет.
9. **ТП рис. 5**: подписи дорожек перекрыты фигурами («S…andbox…ager»).
10. **ТП макеты рис. 37/39**: числа баллов не сходятся с правилом −10 % за подсказку (рис. 39: 80 базовый, 3 подсказки → 62, а по правилу 56). Формула зафиксирована в `02-mvp-spec.md` §6; макеты — иллюстрация, но лучше перегенерировать.
11. **ТП рис. 40**: «срок подтв. 6 месяцев» против 30/90 дней в ТЗ 4.2.

## 5. Риски и как их закрыть

| Риск | Как закрыть |
|---|---|
| Нет доступа к зарубежным LLM API | Любой OpenAI-совместимый endpoint: OpenRouter, российские провайдеры с OpenAI-совместимым API, локально Ollama/vLLM. Шаблонный режим работает вообще без LLM — демонстрация не сорвётся |
| WebSocket-мост терминала к `docker exec` — самая хрупкая часть | Отдельная фаза (Ф6) с интеграционным тестом; два варианта реализации (aiodocker или docker-py в потоке) |
| Backend управляет Docker через сокет = root на хосте | Стенд — отдельная ВМ; в docker-compose опционально `docker-socket-proxy` с ограниченным API; зафиксировать в DEVIATIONS как допущение учебного стенда |
| 95 % совпадения с экспертом не измерить без экспертных оценок | В испытаниях: 20+ сессий, оценка преподавателя через UI корректировки, отчёт расхождений строится автоматически из audit_logs |
| Объём UI | Макеты Claude Design уже есть (`docs/mockups/`) — переносить стили, а не дизайнить заново |
